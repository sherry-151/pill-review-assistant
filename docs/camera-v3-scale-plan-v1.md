# 新相機目標尺度比較與書審前工作計畫

日期：2026-10-25。使用者指定 10/28 書審截止。本計畫不把尚未完成的試驗列為成果，不以展示成功為理由調整門檻或刪除失敗案例。

## 尺度比較結果

手機端使用 `data/splits/yolo-v001-manifest.json` 中訓練集的既有人工框，共 80 個，四類各 20 個。新相機端使用燕麥背景四張單顆原圖，依目視外緣估計矩形，不使用辨識模型預測框，以免漏辨案例無法測量。目視估計框保存於 `data/splits/camera-v3-oatmeal01-size-estimates.json`，不是新訓練標註或正式定位真值。

比較量為「矩形較長邊／影像較長邊」，以及乘以 640 後的近似輸入像素大小。原手機為直幅 3024 × 4032，新相機為橫幅 4608 × 2592；以相同長邊正規化，不能只比較原圖像素數。640 推估忽略整數取捨及補邊，不代表藥錠實際長度。

|類別|手機框較長邊占比中位數|新相機框較長邊占比約值|縮至長邊 640 後 手機／新相機|手機相對新相機的線性比例約值|
|---|---|---|---|---|
|drug001|10.0%|5.1%|64／33 px|1.9 倍|
|drug002|6.9%|3.5%|44／23 px|2.0 倍|
|drug003|16.3%|9.0%|104／58 px|1.8 倍|
|drug004|14.2%|7.7%|91／49 px|1.9 倍|

因此，這批新相機照片中，模型看到的藥錠線性尺度大約只有手機訓練照片的一半。此方向與使用者自述「手機 2×、新相機正常倍率」相容，但不能據此認定手機使用的是光學倍率，也不能直接把兩個相機的 2× 視為等價。

矩形長邊受藥錠旋轉方向、側面姿態及目視框鬆緊影響，四張新相機照片不能代表整個分布。背景面積比例亦受直橫幅差異影響。本結果是尺度落差的探索性證據，不是尺度造成辨錯／漏辨的因果證明。

完整結果：`outputs/camera-v3-scale-analysis-v001/result.json`，包含來源照片雜湊、比較程式與估計框檔雜湊。重現指令（輸出已存在，重跑需更換名稱）：

```bash
.venv/bin/python scripts/compare_camera_scale.py \
  --output outputs/camera-v3-scale-analysis-v001/result.json
```

## 截止前最小試驗

不重拍、不改權重、不改 conf 0.25、imgsz 640、NMS IoU 0.7 或 CPU。只增加一次預先固定的中央取景範圍對照，檢查放大目標後是否有不同輸出。這是新的前處理試驗，不是原整張影像測試，也不是新增獨立測試照片。

1. 保留燕麥背景五張原圖。從每張同一位置擷取中央 1/2 寬、1/2 高，原圖 4608 × 2592 對應固定區域 `[1152, 648, 3456, 1944]`，衍生圖為 2304 × 1296。此區域在長邊縮至 640 時，會使保留物件的線性尺度約為原整張輸入的兩倍。不得按藥品個別移動區域，也不使用模型框決定裁切位置。
2. 在推論前檢視五張衍生圖是否完整包含藥錠，空背景也套同一規則。本批目視估計框皆落在預定區域內，但仍須查看實際衍生影像。若有切斷目標，明確記錄本次區域不適用，不默默改框或刪除案例。
3. 衍生圖另存 `data/derived/camera-v3-oatmeal01-roi2x/`；不覆寫原圖。若實作此目錄，須確認由 Git 忽略，以免照片被提交。保存原圖雜湊、固定區域座標、衍生圖雜湊及程式版本。
4. 以相同原模型與設定測試全部五張，另存 `outputs/camera-v3-oatmeal01-roi2x-mac-cpu-conf025-v001/`，逐張列出原整張與中央區域的類別、框數、信心值及失敗。固定區域不再依結果調整；不以成功照片替換失敗照片。
5. 單顆檢查條件預先定為：四張有藥照片皆正確類別一框，空背景零框。若滿足，才把同一前處理、原圖與模型送至 Pi CPU 重跑核對。通過此條件仍只是五張開發案例，不等同泛化、臨床或即時性能驗證。
6. 若仍辨錯或漏辨，保存結果並停止本輪，不能繼續降低 conf、逐張試裁切或臨時重新訓練以湊出成功展示。若單顆檢查通過且尚有時間，再另拍五個多顆數量比對案例，採固定取景規則，檢查多出、缺少與替換；相機完整流程尚未完成前不改寫為成功。

中央取景也會改變可見背景及有效視野，因此即使改善，也只能寫「固定中央取景前處理後，本批輸出改善」，不能僅據此證明唯一原因是尺度。未來需要固定場景、重複拍攝及獨立測試驗證。
