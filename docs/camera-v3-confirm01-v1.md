## 2026-10-26 補充：分數排序與 Pi 即時能力

使用者觀察正確：drug002 三張的正確類別分數均高於同顆的 drug001 分數，分別為 0.538536 對 0.305115、0.500226 對 0.245635、0.891221 對 0.148666。因此不是完全沒有辨認出 drug002，而是模型對同一物件保留了跨類別重複框。既定評估要求正確一框，不能事後只留正確類別或全圖最高分後回改本次結果。

本次 `agnostic_nms=False`；已核對安裝的 Ultralytics 8.4.177 `utils/nms.py`，其依類別座標偏移進行 NMS，不同類別的重疊框不互相抑制。官方 Predict 文件亦說明 `agnostic_nms=True` 可跨類別抑制低分重疊框：https://docs.ultralytics.com/modes/predict/ 。這可作後續另立版本的後處理對照，但本次未執行；它不能保證修復漏辨，也可能抑制真正互相遮蔽的不同藥品，不能簡化為全圖只取最高分。

原 best.pt 已在 Raspberry Pi 5 CPU 完成既有四十張手機照片評估及五情境數量比對，故「模型能在 Pi 運算」已有實測。四十張評估的平均模型推論為 374.6 ms／張，詳見 [Pi 部署紀錄](pi-deployment-v1.md)。其倒數約 2.7 張／秒僅是階段平均耗時換算，不是相機端到端實測 FPS；該次 batch、影像形狀及處理流程亦不同於未來即時取像。

目前尚未量測新相機連續取像、固定中央取景、推論、數量比對及結果輸出的總延遲與長時間穩定性，也不知道真實出藥節拍、物件在視野中的停留時間及運動模糊。因此「能做現場更新的研究原型」與「能可靠檢查運作中的藥包機」須分開，後者尚未證實。若後續進行現場工程測試，應保留本設定及所有失敗，不以工程測試代表辨識驗收通過；先測靜態擺放連續更新，再量測完整延遲並對照機器節拍。單次載入模型、固定相機設定與不累積舊畫面佇列是待實作項目，本次未修改或啟動 Pi 程式。
