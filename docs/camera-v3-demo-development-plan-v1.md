# 新相機展示開發參數探索計畫

日期：2026-10-25。使用者在固定中央取景對照結束後，要求另行規劃參數探索。前一輪仍依原停止條件結束，不回改其結果。同日後續已完成[低門檻診斷](camera-v3-low-conf-diagnostic01.md)，並依使用者指定測試候選 B：conf 0.10。該組在五張既有開發案例均符合，見[實測紀錄](camera-v3-candidate-conf010-v1.md)。A、C、D 未執行；目前停止其他候選，先凍結 B，等待新照片確認。

## 目標與版本界線

目標是找到可在已知四類、固定取景及照明下運作的研究展示設定，保留所有嘗試與失敗，並量測是否能在 Pi CPU 執行。不是臨床驗證或自動放行，不保證能在書審前成功。不得把顏色直接硬編成藥品類別，或把人工指定的預期答案當成模型結果。

原模型 SHA-256 與先前資料不變。原 conf 0.25、imgsz 640、NMS IoU 0.7 的整張結果及中央取景結果保留為基準。新探索另用 `outputs/camera-v3-demo-dev01/`，每個設定獨立子目錄，衍生圖沿用已固定的中央區域 `[1152,648,3456,1944]`。這五張現在是開發資料，不能當獨立測試集。

原固定程式 `evaluate_camera_minimal.py` 不解除其參數限制；若執行本計畫，另建展示探索程式，保存全部設定、套件版本、模型及照片雜湊、每張每框類別／分數／座標、處理錯誤與耗時。先不重訓、不換模型、不改 NMS、背景或個別裁切，以免一次改太多因素。

## 第一階段 低門檻診斷一次

使用同五張中央取景衍生圖，暫設 imgsz 640、conf 0.001、NMS IoU 0.7、CPU FP32，僅作診斷，不能當展示通過。低門檻可能產生大量雜框，須逐張查看其他類別與空背景，不只看膠囊。

- 若膠囊位置存在 drug004 低分框，記錄分數與重複／誤報，才有理由測試較低的展示門檻。
- 若膠囊主要被辨成其他類別，降低門檻不會把錯誤標籤自動改正，不能只挑想要的框。
- 若仍沒有 drug004 框，進入有限的解析度對照；不能推論模型完全沒有任何內部特徵反應，因為這仍是經過篩選及 NMS 的輸出。

## 第二階段 有上限的小範圍比較

既有中央取景 640／0.25 結果作基準；每次測同五張，最多新增下列四組展示候選，不全排列組合，NMS IoU 固定 0.7、CPU FP32、無測試時增強，裁切區域不變。

|設定|imgsz|conf|檢查目的|
|A|640|0.15|較低門檻是否找回膠囊，且未增加誤報|
|B|640|0.10|只再多試一個較低門檻，保留全部雜框|
|C|960|0.25|增加輸入解析度，門檻回到基準|
|D|1280|0.25|較高解析度對照，同時注意 Pi 耗時及記憶體|

A、B 只有在第一階段看到合理的 drug004 低分框時才執行，否則跳過並記錄理由。C、D 即使改善，也不能據此宣稱已滿足即時需求；實際 Pi 效能需要量測。若發生資源或處理錯誤，保留錯誤紀錄，不把失敗算成零顆。

conf 是輸出保留門檻，imgsz 影響模型輸入大小，IoU 在這裡是 NMS 的重疊框抑制門檻；目前無多框問題，因此不優先調 NMS，也不把它當作補救漏辨的第一手段。參數語意依 Ultralytics 官方 Predict 文件及目前安裝版本核對：https://docs.ultralytics.com/modes/predict/

## 第三階段 選定一組後凍結

候選設定必須讓四張有藥照片皆為正確類別一框，且框確實位於藥品上；空背景零框、處理錯誤零。若多組符合，優先較高 conf，再優先較低 imgsz，並記錄選擇準則。通過只稱為「開發集展示條件符合」，不能報告泛化準確率。

若五張中仍有錯誤，列出表格，不把其他類別藏掉、不從畫面省略失敗框，也不將低門檻輸出手選成成功；本輪到此為止，不在截止前增加第二輪網格或重訓。仍可展示取像、推論及人工確認流程，但需現場標示失敗與系統限制，不能宣稱可靠辨藥。

## 第四階段 新拍與 Pi 核對

選定設定後才重擺並新拍一小批未看過結果的照片：四類各三張（不同位置及旋轉，共十二張），另加三張空背景，共十五張。維持同一距離、背景、照明與全張一致的中央取景；拍攝前記錄實際品項與數量。選定設定在這批評估前凍結。

完整列出十五張結果。若未全數符合，不能臨時改參數後仍稱這批為獨立確認；要改就把這批降為開發集，之後另拍確認集。即使十五張全符合，也只是小樣本的內部確認，不是臨床或跨場域證據。

若符合，再將完全相同的原圖、固定前處理、模型、程式與展示設定放到 Pi CPU 重跑，核對雜湊、逐張框數／類別及定位，並記錄耗時。最後才做五種多顆預期數量比對案例；此時取景規則不可為多顆個別更換，必須確認全部藥物都在有效區域內，並明確把區域外物件列為不支援的操作情境。數量一致仍要求人工確認，不臨床放行。
